Issue Summary

Active Directory Users and Computers, launched using dsa.msc, failed to open on the Windows Server Domain Controller. The command produced no visible error, no popup, and no application window.

Silent MMC failure AD DS healthy Netlogon running Duplicate DNS records found
Important observation: The issue initially appeared to be an Active Directory console problem, but additional DNS validation revealed stale Domain Controller records and missing reverse lookup behavior.

ADUC Troubleshooting Workflow

Verified RSAT and AD DS Tools

Confirmed that the required Active Directory management tools were installed.

Get-WindowsFeature RSAT-AD-Tools
Get-WindowsFeature RSAT-ADDS

Verified Active Directory Services

Confirmed that core Domain Controller services were running.

Get-Service NTDS
Get-Service Netlogon

Ran Domain Controller Diagnostics

The server passed connectivity and service checks.

dcdiag /test:services

Tested ADUC Launch

dsa.msc produced no response, indicating a likely MMC or snap-in issue rather than a service outage.

dsa.msc

Validated MMC Functionality

A blank MMC console opened successfully, and other snap-ins also opened successfully.

mmc.exe
eventvwr.msc
services.msc

Cleared MMC Cache

Clearing the cached MMC profile resolved the ADUC launch issue.

del /q "%appdata%\Microsoft\MMC\*"

Ran System Repair Checks

SFC and DISM confirmed that no operating system corruption was causing the issue.

sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
ADUC Resolution: Active Directory Users and Computers opened successfully after clearing the corrupted MMC profile cache.

DNS Investigation & Cleanup

After ADUC was restored, DNS testing showed that the Domain Controller was resolving correctly by hostname, but nslookup still showed the DNS server as UnKnown.

Observed DNS Output

nslookup DC01

Server:  UnKnown
Address:  10.10.10.10

Name:    DC01.example.local
Addresses:  2001:db8:abcd:100::10
            2001:db8:abcd:100::20
            10.10.10.10
            10.10.10.66

Finding 1: Duplicate A Records

The Domain Controller had multiple IPv4 A records, including a stale address.

DC01 → 10.10.10.10
DC01 → 10.10.10.66

Finding 2: Missing Reverse Lookup

The DNS server appeared as UnKnown because reverse DNS/PTR lookup was not properly configured.

Default Server:  UnKnown
Address:  10.10.10.10

Cleanup Performed

  1. Opened DNS Manager using dnsmgmt.msc.
  2. Reviewed the Forward Lookup Zone for example.local.
  3. Removed stale A record 10.10.10.66.
  4. Retained valid DC record 10.10.10.10.
  5. Created a Reverse Lookup Zone for 10.10.10.x.
  6. Configured Dynamic Updates as Secure only.
  7. Flushed and re-registered DNS records.
  8. Restarted Netlogon to republish DC locator records.

Final Resolution

ADUC Issue

Root Cause: Corrupted MMC cache/profile.

Fix: Cleared cached MMC console files.

del /q "%appdata%\Microsoft\MMC\*"

DNS Issue

Root Cause: Duplicate A records and missing PTR/reverse lookup zone.

Fix: Removed stale DNS records and created reverse lookup zone.

nslookup 10.10.10.10
Outcome: ADUC launched successfully, the stale IP record was removed, reverse lookup was configured, and DNS identity resolution was restored.

Lessons Learned

  • Silent dsa.msc failures can be caused by corrupted MMC user profile cache.
  • Always verify AD DS, Netlogon, and dcdiag before assuming Active Directory is broken.
  • Testing other snap-ins helps isolate whether the issue is MMC-wide or snap-in-specific.
  • Duplicate Domain Controller A records can create inconsistent DNS behavior.
  • Server: UnKnown in nslookup usually points to missing or broken reverse lookup/PTR records.
  • AD-integrated DNS zones should use Secure only dynamic updates.
  • Restarting Netlogon forces the Domain Controller to republish SRV and locator records.
